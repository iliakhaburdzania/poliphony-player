# Polyphony Player

A one-file web app for practising Georgian (and other) polyphonic choral music.
It plays a score's voices together or one at a time, and has a singing mode that
listens to the microphone and scores how well you sing your part.

## Files

- `songs.json` — the song library the user version lists ({ songs: [score, …] }, first = default)
- `studio.html` — redirects to `index.html?studio`
- `index.html` — the whole app: HTML, CSS and JavaScript in one file, no build step. Open it in Chrome or Edge.
- `scores/` — example transcriptions in the app's JSON format (paste one into the "Transcription" box and press Apply):
  - `aghdgomasa-shensa.json` — Easter hymn, 3 voices (the built-in example)
  - `ceduri-mravaljamier.json` — Many Years, 3 staves with a divided bass in bars 4–6
- `tests/` — checks the user may run (`npm install`, `npm run setup`, `npm test`):
  - `pitch-test.js` — the pitch detector and smoothing on synthetic held notes with disturbances
  - `sing-test.js` — singing mode end to end in Chromium, with a simulated singer instead of the microphone
  - `serve.js` — tiny static server used by the tests

The user tests changes themselves. Don't run the tests or a browser unless they ask.

## How index.html is organised (search for the `/* ---------- ... ---------- */` markers)

- `EXAMPLE` (between `/*DATA*/` and `/*END*/`) — built-in score
- `PROMPT` — instructions sent to Claude to transcribe a score picture into the JSON format
- parsing and checking — `normalizePiece`: parses `NOTE:BEATS` tokens, splits stacked notes (`G3+G2:4`) into separate parts, pads bars that don't add up
- engine state / `buildPiece` — turns a piece into `events` ({v, midi, start, dur} in beats), bar starts, fermatas, breaths
- position — cursor, seeking, status line
- audio — Web Audio synth voices (`startPlay`, `stopAudio`, `pausePlay`, `seekTo`, `tick`)
- score view — piano roll on a canvas that scrolls sideways (`geo`, `draw`); press and drag to move the playhead (`scrubStart`/`scrubEnd`; playback pauses while dragging and resumes on release; in editing mode only on the bar numbers or the playhead line, `inScrubZone`)
- transport — Play / Pause / Resume button and the Space key (`togglePlay`)
- singing mode — microphone (`ensureMic`), pitch detection (CREPE neural network via TensorFlow.js: `loadCrepe`, `crepeFrame`, `crepeRun`, `crepeDecode`, `pumpPitch`; `detectPitch` McLeod as offline fallback), steadying (`stablePitch`, time-based), comparison with the chosen part (`singStep`), live meter (`showLive`; when stopped, `listenLoop` keeps it live against the part's note at the cursor, or the nearest note where the part rests), drawn line (`drawSinging`), scoring (`singScore`, `singFinish`)
- MusicXML import (Read score, MusicXML files only) — `musicXmlText` (unzips .mxl), `musicXmlToRaw` (each staff voice → a part, chords → stacked notes, ties merged in a bar, clef 8 → octaveShift), `joinPages`
- editing mode — `ed` state, `edFromPiece` (parts → note lists in plain beats without pauses, ties merged), `edToRaw` (back to bar strings, notes crossing a bar line tied with `~`, a later note cuts the earlier one), `edChange` (undo snapshot + `edRefresh`, which rebuilds the piece and keeps position/mutes/volumes), `edCarve` (moved/pasted/drawn notes cut away what they cover), pointer handlers on the canvas, `drawEdit` (draw() calls it instead of the playback notes; lanes get a fixed px per semitone via `edRanges`/`edLaneH`), keyboard shortcuts
- projects — saved in localStorage `pp.projects` ({id: {name, savedAt, raw}}); `projSave`, `projOpen`, export/import .json
- reading a picture — SVG files are drawn to a 2000 px PNG first (`svgToPng`), since Claude only reads raster images; uses Claude's `sample` capability when running inside Claude, otherwise the Anthropic API with a key the user pastes (stored in localStorage as `pp.apiKey`)

## Score JSON format

```json
{ "title": "...", "subtitle": "...", "tempo": 72, "repeatTimes": 1, "transpose": 0, 
  "voices": [ { "name": "Tenor I", "octaveShift": -12, "lyricsTimed": [{"t": 4, "d": 4, "text": "Mra-"}], "bars": ["E5:.5 E5:.5 E5:1.5 C#5:.5 D5:1", "..."] } ],
  "breathAfter": [2], "fermataBars": [9], "lyrics": ["agh-dgo-ma-sa", "..."] }
```
Pitches as written on the staff; `octaveShift: -12` for treble-8 (tenor) clefs; beats in quarter notes; `r` is a rest; `+` joins stacked notes; a trailing `~` (e.g. `E4:1~`) ties the note into the next note of the same pitch (used by editing mode for notes crossing a bar line).

## Decisions and history

- Recording analysis (audio/video → notes) was built, tested on a real Georgian Voices recording, and then removed at the user's request. Don't bring it back unless asked.
- Only the piano roll view remains (a staff view was removed on request).
- Play is a Play / Pause / Resume button; resuming keeps muted voices as they are. Space toggles it everywhere except while typing.
- Singing mode runs only outside Claude: pages published in Claude can't use the microphone. A published copy without singing mode also exists in the user's Claude artifacts ("Polyphony Player").
- Pitch detection (Nov 2026): CREPE "tiny" model (ml5-data-and-models, pinned commit, loaded from raw.githubusercontent.com with jsDelivr as backup; TensorFlow.js 4.22.0 from jsDelivr/unpkg) when singing mode is switched on. It needs internet and a GPU backend; if loading fails, there is no GPU or inference takes >30 ms, the McLeod detector (`detectPitch`) is used and the panel says so (`pdInfo`). CREPE confidence: start ≥0.5, keep ≥0.35. Readings run async (`pumpPitch` → `feedPitch` → `stablePitch`), and `sing.sungAt` is used for latency compensation. Steadying is time-based: a leap must hold 60 ms (an exact octave or octave+fifth 120 ms). The meter display is smoothed, and the note names have hysteresis so they don't flicker. The user does all testing himself.
- Scoring: on pitch = within the Strictness setting (±75/50/30 cents), close = within twice that (half credit); the first 0.12 s of each note isn't scored; "Any octave" folds octaves.

## Style

Plain JavaScript, no frameworks. Colours are CSS variables on `:root` with dark-mode overrides. Keep the app a single file.

- Transcriptions (Nov 2026): the user gets score JSON by sending pictures to Claude in chat and pasting the result in. The Audiveris helper was built and then removed at his request; don't bring it back unless asked.
- Editing mode (Nov 2026): a mode like singing mode (they exclude each other). Tools: Select/Draw/Split, grid snapping, pitch up/down, cut/copy/paste/delete, undo/redo, add/remove last bar, insert/remove pause at the playhead (`edInsertPause`/`edRemovePause`: silence in all parts, later notes and words shift across the bar lines, bars keep their usual length (`edUsualBar`) and bars are added/dropped at the end; fermata/breath marks follow (`edMoveMarks`); a sounding note is split), "Even out bars" (`edEvenBars`: re-divide into usual-length bars, nothing moves in time); projects saved in the browser.
- Transpose (Nov 2026): "transpose" in the score (−12..12 semitones, optional) is added to every part's octaveShift in `normalizePiece`, so playback, roll and singing targets move; written notes stay. Control in the editing-mode toolbar, `setTranspose` (in editing mode it is an undoable edit; edit parts' `shift` includes it and `edToRaw` subtracts it). Saved with projects.
- Note names in editing mode (labels on notes, octave labels on the semitone guides, the "Selected" line) show the sounding pitch: written + octaveShift + transpose, so they match what is heard and the singing meter.
- Sing to edit (Nov 2026, editing mode): `recStart` (mic via `ensureMic`, mutes the part, count-in clicks, plays from the range start), `recLoop` (pitch per frame via `pumpPitch`, latency-compensated position → plain beats), `recFinish` (Fix pitches: median sung pitch per note, keeping rhythm; New notes: median per grid step, same pitch merged, range replaced). Range = selected notes of the part, or from the playhead's bar until Stop/Space. "Match the part's octave" shifts the whole take by whole octaves. One undo step.
- Two versions (Nov 2026): `index.html` (hosted on GitHub Pages at iliakhaburdzania.github.io/poliphony-player) is the user version: song list from songs.json, listening, singing mode. `?studio` (studio.html) adds the studio-only panels (class `studio-only`: reading scores, editing mode + projects, transcription) and "Add to song library" (`libAdd`, downloads an updated songs.json for the user to commit). `STUDIO` flag, `loadLibrary`, `chooseSong`, `showLibrary`; the user version remembers the last song (localStorage `pp.song`). EXAMPLE (built-in default) is the user's Ceduri Mravaljamier version (transpose -2, 4 parts, tempo 72); keep it equal to the first song in songs.json. Transpose: in the studio in the editing toolbar (`keyDown/keyUp/keyOut`); in the user version a second control in the playback bar (`keyDown2/keyUp2/keyOut2`, class `user-only`; double-click returns to the song's published key; not saved).
- Parts carry `src` (transcription voice index; stacked notes split one voice into several parts). Clicking/caret in the Transcription box (`jsonCaretBar`) highlights that bar (`hiBar`) and moves the playhead. (A click-a-note bar editor existed briefly and was replaced by lyric editing at the user's request.)
- Lyrics on the notes (Nov 2026): every part has its own timed lyrics, `voices[i].lyricsTimed: [{t, d, text}]` in plain beats (no pauses); an older top-level `lyricsTimed` is read as the first part's. Parts without them get the per-bar `lyrics` spread over their own note starts (`lyDerive`); `lyrics` (per bar) follows the first part (`lyPerBar`). Drawn above each part's notes, each word in a bordered box exactly as long as it lasts (`drawLyrics`, height from `lyBase`, 18 px above the note; lanes get `lyPad()` extra room at the top when there are lyrics; only the box grabs a word, its right edge resizes, so notes stay clickable; current word coloured while playing, both versions). Studio: click a word → editor (`lyOpen`, Enter applies + next), drag the box's right edge = duration of that word only (the next word never moves; it can grow up to the next word's start), drag the word = move (a joined previous word ends where it now starts, a joined next word starts where it now ends), double-click empty space in a lane = add; all via `lyCommit(part, fn)` (undo step in editing mode, where parts keep `lyr`). Pause insert/remove and bar removal keep lyrics in step. (Earlier a separate Lyrics line under the voices was used; replaced at the user's request.)
- Publishing: `.nojekyll` makes GitHub Pages serve the files as they are (no Jekyll). `BUILD` (near the end of the script) is shown in the header; update it with every change so the user can tell which version a browser has.
- Saving (Nov 2026, studio): one Save button (Ctrl+S) writes the current song into songs.json in the app folder via the File System Access API (`songSave`, `songsFile`; the file handle is kept in IndexedDB "polyphony"/kv/songsFile, the browser asks for the file once and later only for permission). The studio reads its song list from that file (`studioLibrary`, "Open songs.json" button when permission must be re-granted). The user then commits and pushes to publish. Song replaced by the key it was opened with (`songKeyLoaded`), else by title. Projects/export/import/"Add to song library" UI is hidden (code kept; `libAdd` is the fallback for browsers without the API). The user explicitly does NOT want Save to push to GitHub.
- Words are edited only in editing mode (`lyHit` requires `ed.on`), so every word change is an undo step; with a word selected: ←/→ (`lyNudge`), Delete, Esc; Ctrl+Z/Y work inside the word box when there is no unapplied typing.
- The player opened from the folder (file://) can't fetch songs.json, so `loadLibrary` reads it through the studio's stored file link (`songsFile(false)`; a "Show saved songs" button when the browser wants a click first). After the library loads, the player always loads the library's version of the song, even if the built-in EXAMPLE has the same title.
- Several words (Nov 2026, editing mode): `ly.multi` = selected words [{v, t}] (Shift/Ctrl-click, box select together with notes via `lyBoxSelect`; a click elsewhere deselects). Ctrl+C/X (`lyCopy`, one part's words), Ctrl+V (`lyPaste`: into the part last clicked, at the clicked moment, else at the copied moment; overlapping words replaced), Delete (`lyDeleteSel`); multi-part changes are one undo step via `lyChangeAll`. `ed.lastCopy` decides whether Ctrl+V pastes notes or words.
- Layout (Nov 2026): the playback bar (section .transport) sits directly under the score view; the per-bar lyrics row under the score is hidden (words are shown on the notes) and the hint line above the score was removed (help lives in the editing panel).
- Stretching a note longer (editing mode, right edge) moves the later notes and words of that part later by the same amount instead of cutting them (bars added at the end when needed); shorter leaves a rest. Moving/drawing/pasting notes still cuts what they cover (`edCarve`).
- Stretch and clipboard (12 Nov 2026): stretching a note longer first uses up the rest after it; later notes move only as far as needed not to overlap (`edPush`, cascading; also drives the drag preview), each word moving with the note it sits on. This replaces "moves the later notes by the same amount" above. Copy/Cut (`edCopy`, `edCut`) take the selected notes and words together (`ed.clip` + `ed.clipWords`, common start); `edPaste` puts both at the playhead in their own parts as one undo step (through `lyChangeAll`), replacing words in the way. Words alone still use `lyCopy`/`lyPaste` (`ed.lastCopy === 'words'`). Delete with notes and words selected removes both (`lyDeleteSel(true)`).
- Crossing drag (12 Nov 2026): where a note touches the next one, `edHit` returns `joint` for the last 3 px (plain edge zone is the 7 px left of that). A joint drag is a resize with `d.ripple`: all later notes and words of the part shift by the same amount, shorter or longer. `ed.hover` ({v, id}, set by `edHover` on pointermove) makes `drawEdit` show an accent line with arrows at the crossing and outlines on the notes that will move; the same cue shows during the drag. Cursor col-resize.
- Words into another part (12 Nov 2026): a box over words usually catches notes too, so `edCopy` also fills `ly.clip` with the first part's words; `edPaste` hands over to `lyPaste` (words only, into the clicked part) when a part outside the clip was clicked since the copy (`ly.target`). Otherwise notes + words go to the playhead in their own parts.
- Word click (12 Nov 2026): the first click on a word only selects it (`lyOpen(v, i)` shows the word panel without focusing the text box, so Delete/Backspace, arrows and Ctrl+C act on the word); a click on the already selected word, Enter, a double-click-added word, Prev/Next and Enter-to-next pass `edit = true` and put the cursor in the text box.
- Word snapping (12 Nov 2026): dragging a word, its right edge, adding one or choosing the paste spot uses `lySnap(v, t)`: the grid, or a note start/end of that part when nearer (within 8 px). Needed for notes off the grid (e.g. the 0.75 + 0.25 pair in bar 18 of Ceduri with a 1/2-beat grid).
- Last bar (12 Nov 2026): the user wants every bar the same length, the last one included. "Even out bars" pads the last bar to the usual length (rest) instead of leaving a remainder, and "add bar" adds a bar of the usual length (`edUsualBar`). Ceduri bar 25 was 2 beats (old remainder) followed by a 4-beat rest bar; now 26 bars of 4.
- Piano view (12 Nov 2026, both versions): button "Piano view" (`pianoOn`) in the score panel swaps the roll for a second canvas (`#piano`): notes fall onto a keyboard (`drawPiano`, `pvLayout`, state `pv`; `draw()` hands over to it while `pv.on`). Time runs down at 44 px per beat × `zoom`; key range = C to C around the song's sounding pitches; voices coloured, unisons nested narrower, sounding keys lit (striped when shared), words shown where their note starts, bar lines numbered. Drag the falling area to move through the song (pauses, then resumes), press a key to hear it (`edPreview`). Remembered in localStorage `pp.piano`. Editing mode switches it off (needs the roll); singing mode works with it but the sung line is only drawn on the roll.
- Choir sound (12 Nov 2026): "Sound" select in the playback bar (`soundMode`, localStorage `pp.sound`): "Choir, words" (default), "Choir, aah", "Plain" (the earlier two-sawtooth sound, kept). Choir = three detuned sawtooth singers per note with their own vibrato → lowpass tilt → four bandpass formant filters per voice (`CH_VOWELS` bass/tenor/alto by the part's average pitch, `CH_GAIN`, `CH_Q`) → `artic` gain → stereo pan → voice gain; master also feeds a generated convolution reverb (`choirRoom`). `choirWords` automates the formants along each part's timed words (`choirParse`: Georgian and Latin letters → vowels a e i o u, consonant kinds son/fric/stop): onset consonant just before the word start, coda just before its end; sonorants as a nasal formant shape, fricatives as band-passed noise (`choirHiss`), stops as a short closure + click. Not speech synthesis: vowels are clear, consonants hinted. Levels and timings were set without listening; the user tunes by ear.
- Sung line (12 Nov 2026): the lane of the part being sung shows 4 semitones more at both ends (`laneRange(v)`, used by the notes, words and the sung line) and lanes are 24 px taller in singing mode; before, a pitch more than about 2 semitones under the part's lowest note was pinned to the lane's bottom edge. Pitches still beyond the lane are drawn dotted along its edge.
- Piano score export (12 Nov 2026, studio): "Export piano score" next to Save downloads `<title> (piano).musicxml` (`pianoScoreXml`): one Piano part, two staves, sounding pitch; upper half of the voices on staff 1, lower half on staff 2, each voice its own MusicXML voice with stems up/down; clef per staff by average pitch (G if ≥ A3, else F); key signature chosen for fewest accidentals (`mxKey`); 48 divisions per quarter, lengths split into tied written values (`mxSplit`, triplets as 3:2 without brackets); ties across bars, fermatas, tempo, and the first voice's words as lyrics. Not a rendered PDF: the user opens it in notation software.
- Piano PDF (13 Nov 2026, studio): "Export piano PDF" (`pianoPdf`) feeds `pianoScoreXml()` to OpenSheetMusicDisplay 1.9.0 (loaded on first use from jsDelivr, unpkg as backup; global `opensheetmusicdisplay`; canvas backend, `pageFormat: 'A4_P'`, drawn into an off-screen box whose width × devicePixelRatio ≈ 2200 px, `osmd.zoom = boxWidth / 1100` so the layout is that of an 1100 px page), turns each page canvas into a JPEG and writes the PDF itself (`pdfFromJpegs`, one A4 page per picture, no library). Pages are pictures so Georgian words need no embedded font. 2.x of the library exists but was days old and unknown; 1.9.0 was chosen on purpose. "Export MusicXML" (`pianoExport`) stays for editing in notation software.
- Song end (13 Nov 2026): a pass ends where the last note ends, or at the optional `"end"` of the score (plain beats; set in editing mode with "End here" at the playhead, removed with "End at last note"; `meta.end`), not at the end of the last bar. `FULL` = timeline length of all bars, `END_TL` = `songEnd()`, `PASS` = `END_TL` outside editing and `FULL` in editing mode (`setPass()`, called by `buildPiece` and when editing is switched on), so the player, repeats, the seek bar and singing mode stop at the end while the editor keeps the spare bars, with the end drawn as a dashed red line and the rest greyed (`edEndPlain`). `startPlay` cuts notes and words at `PASS`; pause insert/remove move the end line; the piano score export stops at the bar holding the end. Add the `end` field to the score format above.
- No built-in song (13 Nov 2026, at the user's request): `EXAMPLE` and the "Load the example" button are gone; songs always come from songs.json (second song: Aghdgomasa Shensa, copied from scores/). Between `/*DATA*/` and `/*END*/` there is only `BLANK`, one silent bar the page stands on until the library has loaded. `loadLibrary` opens the remembered or first song in both versions; when songs.json can't be read it shows "No song loaded" and says why (file:// or offline). Save refuses to save `BLANK`. Everything above about EXAMPLE and keeping it equal to songs.json no longer applies. tests/sing-test.js still speaks of the built-in example and was not updated.
- Score layout of the exports (13 Nov 2026, replaces the two-staff piano layout above): `pianoScoreXml` writes one MusicXML part per staff: every voice its own staff, except voices named bass/bani/ბან…, which share one staff as two voices (stems up/down, part name "Bass"). Clef: treble-8 (G clef, clef-octave-change -1) when the voice is written an octave up in the song (octaveShift ≤ -12), else G or F by average pitch. Each staff shows the words of its first voice. PDF draws part names. Button label "Export PDF"; the files are still named "<title> (piano)".
- Grips at a crossing (14 Nov 2026, replaces the pixel zones in "Crossing drag" above): in a melody where every note touches the next (Aghdgomasa Shensa) the user could not shorten a single note, because the joint zone covered the end of short notes. Now `edHit` puts the two grips on different sides of the crossing: inside the note, its right half up to 8 px = resize only this note; from the note's end to 4 px past it (the start of the next note) = joint/ripple. Candidates are ranked joint > edge > body, so a same-pitch neighbour's body never hides a grip.
- Grid (14 Nov 2026): added 1/8 and 1/16 beat to the editing grid; the shortest note or word is one grid step, 1/16 beat at the smallest (also the limit with the grid off). Grid lines are only drawn when they are at least 7 px apart, so zoom in for the fine grids.
- Help text (14 Nov 2026): the three long help paragraphs in the editing panel (Sing to edit, Words, Drag a note) were removed at the user's request; only the one-line status (`edInfo`) and the buttons' tooltips remain. Don't add long help text back to that panel.
- Singing count-in (14 Nov 2026, both versions): with "Starting note and count-in" ticked (singing panel, `singCount` checkbox, localStorage `pp.singCount`, on by default), Play in singing mode first sounds the sung part's next note (at the playhead, or the first one after it; triangle tone held through the count-in) and clicks one bar (≥ 2 beats, `recClick`), then `startPlay` from the playhead (`singCountIn`). Play/Space during the count-in cancels (`singCountStop`); switching singing mode off cancels too.
- Pitch reading fixes (14 Nov 2026; user: headphones + CREPE, wrong notes and jumping; not verified by ear): (1) the microphone is opened WITHOUT echo cancellation unless "Speakers (no headphones)" is ticked (`singSpk`, localStorage `pp.singSpk`, `micReset` reopens the stream): the canceller garbles a voice singing the same notes as the music and makes Windows duck the music. (2) `crepeDecode(act, near)` only looks at bins 56..307 (about 60–1100 Hz) and keeps the held note (`sing.stable`) when the strongest bin is elsewhere but the held note's bin is still ≥ half as strong. (3) `crepeRun` returns the median of the last three voiced readings; confidence start 0.55 / keep 0.4 (was 0.5 / 0.35). (4) analyser size grows with the sample rate (CREPE needs 64 ms: at 96 kHz the old 4096 samples made it read a fifth low), 55 Hz high-pass before the analyser, basic detector window scales with the sample rate. `stablePitch` and `detectPitch` themselves are unchanged (tests/pitch-test.js covers them).
- Singing result popup (15 Nov 2026): `#singResult` is now a modal (`.respop` backdrop + `.rescard`): score in a ring that fills while the number counts up, up to five stars, grade, "New best!" badge, the same stats and practise-bar buttons, Sing again / Close (also ×, Esc, click beside the card). `singCelebrate(score, isBest)`: from 75 points or a new best, confetti on a full-screen canvas (`#rConf`) and a short fanfare; calm for low scores; no motion with prefers-reduced-motion. All existing code still shows/hides it through `hidden`. The count-in's starting note now sounds for the first half of the count-in only.
- Phones (15 Nov 2026): below 760 px a fixed bottom bar (`#miniBar`, Play/Pause + title + bar + time) appears while the playback panel is out of view (IntersectionObserver); it mirrors `#playAll`, `#status`, `#seekOut`, `#title` through MutationObservers and calls `togglePlay`. Touch on the score (not editing): a swipe scrolls it natively, a tap (< 10 px) seeks (`tapScore`); mouse/pen keep press-and-drag scrubbing. `pointer: coarse`: 44 px buttons/selects, larger checkboxes and sliders, 16 px text in fields (no iOS zoom on focus). Narrow layout: song list one per row, voice rows "name | Hear | ▶ Only" with the volume below (" this voice" hidden), Play full width, tighter padding. Built without looking at it in a phone browser.
- Words that don't fit (15 Nov 2026): `drawLyrics` draws a part's boxes first, then its words: a word too wide for its box is set smaller (12 → 9 px); if it still doesn't fit it is drawn whole in a tag just above its box (left-aligned with the word, a short line down to the box), on a second row when the previous tag is in the way. Click/drag still work on the box (`lyHit` unchanged).
- Line timing (15 Nov 2026; user: on a phone the sung line was late): latency compensation goes through `singLatency()` (singing mode `singStep` and Sing to edit `recLoop`): the browser's reported output + base latency, at least 0.09 s on phones/tablets (they often report too little), plus the mic's reported latency, plus the "Line timing" slider (`singAdj`, -200..+500 ms, localStorage `pp.singAdj`, double-click resets). Moving it right shifts the line left (earlier). The scoring uses the same shift.
- Microphone choice (15 Nov 2026): "Microphone" menu in the singing panel (`singMic`, localStorage `pp.singMic`, "" = default). `ensureMic` asks for that deviceId exactly and falls back to the default (clearing the choice) when it is gone; `micList` fills the menu from enumerateDevices (names only after permission; refreshed on devicechange and after the mic opens); changing it reopens the stream (`micReset`). Also used by Sing to edit. iPhones may list a single microphone: iOS routes the input itself.
